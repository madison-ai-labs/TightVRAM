One machine, one build

Every number comes from one machine: RTX 3070 8 GB on PCIe 3.0 x16, i9-10850K, 2 × 16 GB DDR4-3000, Ubuntu 26.04, llama.cpp build b12156 (45b6604b2) compiled with CUDA 12.4 for arch 86. Model files are verified by SHA256 against the Hugging Face LFS checksums. Comparisons are only valid within one build. When the build changes, the baselines are measured again.

Separate processes, alternating order

Generation speed scatters between 30 and 37 t/s across processes with identical parameters, while the repetitions inside one llama-bench process agree to a few tenths. The ± that llama-bench prints is therefore not the uncertainty you care about. So:

  • every arm runs in several separate processes, usually three, often six;
  • arms alternate (ABBA, ABCDDCBA, Latin squares, randomized blocks with a fixed seed) so drift over time doesn’t look like an effect;
  • differences under about 3 t/s from single runs count as nothing.

Real text, real server

llama-bench feeds random tokens. For an MoE model that changes the routing: a 4096-token batch of random tokens uses 85 % of the experts, while real text uses 98 %. That made llama-bench report 10 % more prefill than the server delivers. Decisions are based on llama-server with the exact production arguments and real text (source code and documentation, sent as token arrays, cache disabled), or on replays of real agent sessions with tool calls.

Rules before results

For the larger experiments, the decision rule was written down and committed before the measurement window opened. For example: “a winner needs a median of at least 1.15× baseline, a minimum above the baseline’s maximum, end-to-end time per prompt at most 5 % worse, valid tool calls, and a VRAM peak of at most 7,680 MiB.” MTP missed that last one by 7 MiB, and it stayed out. A rule you bend after the fact isn’t a rule.

Measured, calculated, claimed

The lab notes mark every statement as one of three things:

  • measured: we ran it and have the raw data;
  • calculated: derived from measured parts, not run as such;
  • claimed: someone else’s number or explanation, not checked.

Certainty is stated explicitly (high, medium, low), together with the reason. “The routing is skewed” is high: six prompts and 3,844 generated tokens. “A 2 GiB saving from deriving the mask” is calculated, and nothing was started.

Check that the harness measures what you think

  • The profiling build’s timers cost 0.5 % throughput, which was measured against the unpatched binary.
  • The quant harness had to reproduce the shipped tensors exactly before any of its other numbers counted.
  • The allocator dump had to match the failing cudaMalloc size to the byte.
  • A routing trace that produced plausible-looking numbers was wrong twice (a non-contiguous view, a layer that only computes one row in prefill). It was caught by an invariant check: marker tokens must equal routing rows.
  • A run that coincided with another job on the machine (a benchmark suite in containers) was declared invalid and repeated. A watchdog checked the machine every 30 seconds during the repeat.

Corrections stay visible

When something turns out wrong, the correction goes next to the original statement, with the commit that made the mistake. Examples on this site: the “solved” RAM bandwidth question, a mixed-up baseline in a prefill estimate (1,650 → 2,260 should have been 1,577 → 2,257), and a code reference that pointed at the wrong attention path.

Shared machine

The GPU is shared by several sessions and a production server. Heavy measurements run in a claimed window: the server is stopped through its service tool, the card is claimed, and the server is restored and health-checked afterwards. Other sessions’ experiments are never interrupted to make room.

What we don’t claim

Small samples are called small. Three seeds per tool-use scenario give a 95 % upper bound of 0.21 on the failure rate, and that is written next to the score. Outputs that differ at temperature 0 are reported as “different”, not as “worse”. Quality was not part of those measurements.
