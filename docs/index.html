Pushing a 35B model through an 8 GB card

Efficient inference

Three weeks of measuring Qwen3.6-35B-A3B on a gaming PC with an RTX 3070. We kept the wins, wrote down the failures, and published the raw data.

An 8 GB card can run a 35B model at 36 tokens per second and read prompts at 2,400 tokens per second, if you know which wire you are waiting on.

Prompt processing, 16k tokens
was 1,402 t/s 2,438 t/s Pinned memory and a 187-line expert prefetch patch. Output is bit-identical. Real text, llama-server, same build.
Same, with a 64k context profile
was 1,402 t/s 3,590 t/s Doubling the micro-batch to 8192 only fits if you give up half the context.
Generation
was 31.2 t/s 36.5 t/s Almost all of it from turning on XMP. Every other idea for generation did nothing, made it slower, or cost more somewhere else.

  1. INF-012

    Does PCIe 4.0 remove the prefill bottleneck?

    Prefill on this machine waits on expert uploads over PCIe 3.0. The card and the board can do Gen4, the CPU can't. We calculated what a CPU swap would give. Nothing has been measured yet.

    4,000–4,500 t/s calculated

  2. INF-011

    Prefetching experts: +45 % prefill in 187 lines

    Prefill spends 59 to 65 % of its time uploading experts, and llama.cpp does that strictly before computing each layer. Loading the next layer's experts on a second CUDA stream gave +37 to +50 %, with bit-identical output. It's now in production.

    pp16k 1,629 → 2,438 t/s
    Measured✓ Kept
    25 Nov 2026
  3. INF-010

    Quant formats as a transport problem

    We quantized real expert tensors of Qwen3.6 into 30 formats and measured error, CPU decode time, GPU time and upload cost for each. On this machine the right question isn't "how many bits" but "how many bytes per millisecond of unpacking".

    Q3_K: −21 % tg time, 2× the error
